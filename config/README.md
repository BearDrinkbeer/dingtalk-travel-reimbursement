# 私有部署配置

仓库只保留通用代码和示例配置。实际公司的钉钉标识、应用凭据、管理员 userId、审批
`processCode`、表单字段 ID、Schema 指纹及选项映射都不得提交到 Git。

部署时按以下方式配置：

1. 复制根目录的 `.env.example` 为 `.env`，在本机或服务器填写实际值。`.env` 已被
   Git 忽略。
2. 在 `.env` 的 `ADMIN_USER_IDS` 中至少保留一个初始管理员。登录后，该管理员可以在
   “系统设置”中维护页面标题和其他管理员 userId；配置文件中的管理员始终保留，避免
   误操作导致无人能进入设置页。
3. 以管理员身份打开“系统设置”，读取并确认报销、境内出差、境外出差审批模板。
   模板映射保存在运行时数据库中，不需要把真实 Schema 导出文件提交到仓库。
4. 本地联调可运行 `make dev-dingtalk-prod`；容器部署使用 `make deploy`。

如确实需要在本地导出模板或诊断数据，请使用 `*.private.json` 文件名。此类文件以及
`production-oa-*.json` 已被 Git 忽略，只能作为短期本地资料使用。

公开仓库时应通过 Git 提交或导出受版本控制的文件，不要直接压缩整个工作目录；被
忽略的 `.env`、运行时数据库、上传材料和临时诊断文件仍可能存在于本机目录中。
