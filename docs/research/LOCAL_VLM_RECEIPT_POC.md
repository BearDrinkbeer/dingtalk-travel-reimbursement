# 本地多模态小模型票据 PoC

日期：2026-09-01  
状态：通用模型与 PaddleOCR-VL 1.6 离线对比完成，未接入报销主流程

PaddleOCR-VL 1.6 的完整测试见 [`PADDLEOCR_VL_16_LOCAL_POC.md`](PADDLEOCR_VL_16_LOCAL_POC.md)。

## 结论

在当前 MacBook Pro（Apple M5 Pro、48 GB 统一内存）上，本地 2B 视觉模型可以在热态约 1–2.3 秒内直接从图片生成结构化票据候选，并完成类别判断。但测试也出现了财务上不可接受的“选中税额或未税金额”问题，因此不能直接替换现有的 PDF 文本层 / PP-OCRv6 + 确定性 Parser。

本轮更合适的落地方向是：保留现有 OCR 负责文字、金额和日期，Qwen3-VL 2B 仅作为类别与说明的候选来源，或者只在当前 Parser 返回 `other` 时兜底。所有结果仍须经过金额、日期、类别白名单和人工编辑流程。

## 测试条件

- 模型服务：Ollama 0.33.2，本机离线推理，不调用云端 API。
- MiniCPM-V 4.6：`minicpm-v4.6:q4_K_M`，1.6 GB。
- Qwen3-VL 2B Instruct：`qwen3-vl:2b-instruct-q4_K_M`，1.9 GB。
- 样本：10 张，覆盖广告、机票空白样张、通讯、咨询、招待、劳务、租赁、住宿、办公和水电；其中 9 张非空票据参与准确率统计。
- 输入：图片直接送入模型，不预先提供 PP-OCR 文本。
- 输出：受 JSON Schema 约束的 `category / event_date / invoice_date / amount / description / evidence`。
- 参数：关闭思考、温度 0、固定 seed、单张串行。

以上为 2026-09-01 的历史结果。其中所谓“咨询”样本的目录名有误，票面实际为劳务费且当时按劳务费判分；该重复样本已于 2026-09-02 从本地测试集和复现实验脚本移除，历史统计不追溯改写。

## 结果

| 模型 | 类别精确匹配 | 总金额精确匹配 | 热态平均耗时 | 观察 |
|---|---:|---:|---:|---|
| MiniCPM-V 4.6 Q4 | 1/9（11.11%） | 4/9（44.44%） | 1.34 秒/张 | 指令遵循和类别稳定性不足 |
| Qwen3-VL 2B Instruct Q4 | 7/9（77.78%） | 7/9（77.78%） | 0.99–2.28 秒/张 | 两次热态运行有波动；仍会选错金额字段 |
| PaddleOCR-VL 1.6 完整管线 + 确定性金额提取 | 不直接输出公司类别 | 9/9（100%） | 45.14 秒/张 | 金额最稳，但峰值约 11.4 GiB |
| PaddleOCR-VL 1.6 文本 + Qwen3-VL 2B 分类 | 8/9（88.89%） | 沿用上行 9/9 | 额外 0.22 秒/张 | 上游漏掉关键项目名时仍无法分类 |

Qwen3-VL 首次加载并处理第一张图片曾观察到约 15.6 秒；模型驻留后的两次完整运行平均分别约 0.99 秒/张和 2.28 秒/张。这里是开发机单并发数据，不能推导目标 Linux CPU 服务器的速度。

Qwen3-VL 的主要错误：

- 文件目录名为咨询服务、但票面项目实际为“劳务费”的发票被分类为“其他”，总金额 500.00 正确。
- 招待费发票选择未税金额 2117.82，正确价税合计为 2139.00。
- 办公用品发票选择税额 6.49，正确价税合计为 56.43，同时分类为“其他”。

空白机票样张能识别为机票且未臆造日期和金额。当前样本多数是只含开票日期的普通发票，因此本轮没有对“乘车日期/服务日期与开票日期分离”计算准确率；这一项仍须用带人工金标准的交通票据另测。

## 工程判断

### 可以采用

1. 在开发环境增加 shadow 识别：现有 OCR 正常返回，同时把同一图片送给 Qwen3-VL，仅记录脱敏后的结构化候选和耗时。
2. 优先使用 Qwen3-VL 补充类别和说明；现有 Parser 已有明确结论时不覆盖。
3. 金额继续以“价税合计 / 票价 / 实际支付金额”的确定性规则为主。VLM 金额与 OCR 候选不一致时标记人工检查，不能静默采用。
4. 发生日期与开票日期分别保存；交通票据没有明确发生日期时不得用模型猜测。

### 暂不采用

1. 不让 VLM 单独决定 Excel 中的金额和日期。
2. 不让模型直接生成 Excel 或覆盖用户姓名、部门、项目等业务字段。
3. 不把模型运行时直接塞进 FastAPI Web 进程；正式接入时应保持独立本地进程、单并发和超时回退。
4. 不因为 9 张样本结果就默认在生产环境对每张票据调用。

## 复现

评测脚本：`scripts/research/evaluate-vlm-receipts.py`

```bash
ollama serve
ollama pull qwen3-vl:2b-instruct-q4_K_M
backend/.venv/bin/python scripts/research/evaluate-vlm-receipts.py \
  --model qwen3-vl:2b-instruct-q4_K_M \
  --output outputs/vlm/qwen3-vl-2b-full.json
```

完整结构化结果位于：

- `outputs/vlm/qwen3-vl-2b-full.json`
- `outputs/vlm/minicpm-v4.6-full.json`

评测输出不保存完整 OCR 原文，但测试图片本身仍按项目的私有测试数据处理。
